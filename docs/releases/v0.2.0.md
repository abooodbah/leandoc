# LeanDoc v0.2.0

LeanDoc 0.2.0 takes the look of LeanMark 0.6.0, the other Lean viewers'
reference. It adds two softer dark themes, Dim and Dusk, a settings panel
with every keyboard shortcut, and a page colour setting: keep the page white
like paper, or give it the theme's colours. Find, zoom, and the switch
between page and reading view do less work.

## Release assets

| Platform | Artifact |
| --- | --- |
| Windows 10 and 11, x64 | **LeanDoc-v0.2.0-windows-x64.zip** |
| Ubuntu 24.04 and compatible, x86-64 | **LeanDoc-v0.2.0-linux-x86_64.deb** |
| macOS 12 or later, Intel and Apple silicon | **LeanDoc-v0.2.0-macos-universal-preview.zip** |

Every artifact has an adjacent **.sha256** sidecar. The macOS preview also has
a **.metadata.json** file that records how it was signed.

## New

- **Dim and Dusk.** LeanMark's two softer dark themes, with its colours.
  The theme button and Ctrl+Shift+T step through System, Light, Dark, Dim,
  and Dusk, and LeanDoc remembers the choice.
- **Theme dot.** The theme button shows a dot in one colour per theme, and
  its tooltip names the theme. System says which theme it shows, for
  example "Theme: System (Dark)".
- **Settings panel.** The settings button, Ctrl+/, or F1 opens a panel
  beside the document with the theme, the view, the page colour, the zoom,
  and every keyboard shortcut. Escape closes it.
- **Page colour.** White like paper, as before, or the theme's colours. On
  a dark theme the document's own colours are turned to the theme so its
  text stays readable. LeanDoc remembers the choice.
- **LeanMark's look.** The toolbar, the tab strip, and the current section
  in the outline look as they do in LeanMark.

## Fixes

- After a long jump, with the scroll bar or Find, the outline could mark a
  section several entries away from the one on screen. It now finds the
  current section again once scrolling stops.

## Speed and memory

Measured with the 300-page test report in the Linux build, on the same
machine for 0.1.4 and 0.2.0:

- Find waits for a short pause in typing; Enter and F3 search at once.
  Typing a six-letter word held the window for up to 441 ms after a key in
  0.1.4 and for 103 ms in 0.2.0.
- Zoom steps that come together, from Ctrl+wheel or a held key, are laid out
  once: three steps took 820 ms and now take 314 ms.
- After the first switch to each view, switching to reading view takes
  551 ms instead of 921 ms and back to page view 837 ms instead of 963 ms.
  The document is not parsed again.
- Marking the current section no longer changes its weight. Scrolling
  through the report lays the page out 725 times instead of 1,039.

Opening a document: in the Linux build, the 1,000-page report shows its
first page in 2,261 to 2,290 ms (0.1.4: 2,243 to 2,791 ms in the same
alternating runs); in Chromium the 300-page report renders in 555 to 572 ms
(0.1.4: 528 to 560 ms). On the Windows CI runner (same processor model,
private bytes of the whole process tree) the 300-page report showed its
first page in 1,282.5 ms against 1,114.5 ms for 0.1.4, the 1,000-page report
in 2,312.5 ms against 2,418.5 ms, and memory with 1,000 pages was 386.3 MiB
against 385.3 MiB. LeanDoc.exe is 582,656 bytes (0.1.4: 581,120).

## Known gaps

- A page that follows a dark theme turns every document colour to the
  theme; pictures keep their own colours.
- Zoom still lays out the whole document once per step.
- The Windows and macOS builds were checked in CI only; the owner's
  measurement run on a reference laptop is still to come. One Windows CI
  pair measured the 300-page first page 15 percent slower than 0.1.4; the
  reader itself renders it 2 to 5 percent slower in Chromium, and CI runners
  vary by more than that between runs.

## Installing

On Windows, run the installer from the extracted ZIP:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\installer\install.ps1 -OpenDefaultAppsSettings
```

## Signing and privacy

The Windows programs in the GitHub ZIP are not signed.

Privacy policy: This program will not transfer any information to other networked systems unless specifically requested by the user or the person installing or operating it.
LeanDoc's own code makes no network requests and never fetches anything a
document points to. The page is drawn by the system web runtime (the Microsoft Edge WebView2
Runtime on Windows, a Microsoft component), which may contact its vendor on
its own. The full policy, including how to uninstall, is in the
[README](https://github.com/abooodbah/leandoc#privacy-policy).
