## Phase 1 streams

The streams share only the contracts committed in phase 0:
[`src/core/DocCore.h`](../src/core/DocCore.h) (core API) and SPEC section 4.3
(reader and host protocol). Each stream owns its files exclusively; a stream
that needs a change in another's files records it in its handoff note instead.

### Stream A: core, security, and inspect tool

Owns `src/core/`, `third_party/miniz/`, `third_party/pugixml/`,
`tools/inspect/`, `tests/core/`, `tests/fixtures/` (generator and all
fixtures), `tests/corpus/`, and a `CMakeLists.txt` section for
`leandoc_core`, `leandoc-inspect`, and core tests.

- Vendor miniz and pugixml (single-file sources, licences kept).
- Implement every function in `DocCore.h` per SPEC section 3.
- Write `tests/fixtures/make-fixtures.py` producing every security fixture in
  SPEC section 6 and every feature fixture in SPEC section 7; commit outputs.
- Core tests for each fixture, limits, JSON shape, outline, sanitized package
  (re-open it with the core and check no forbidden part or attribute remains;
  where `soffice` exists, convert it headless).
- Corpus fetch and run scripts with `manifest.json` (source URL and licence per
  file).

### Stream B: reader

Owns `assets/`, `package.json`, `package-lock.json`,
`scripts/stage-runtime-assets.mjs`, `tests/reader/`, and the JS rows of
`THIRD_PARTY_NOTICES.md` (written as `docs/notices/reader.md` for merge).

- Adapt LeanMark's reader shell, CSS tokens, find, tabs, theme, and bridge.
- docx-preview integration, page and reading views, zoom, outline, fidelity
  bar, fallback pages, empty state with recent files, open-in-editor button,
  post-processing fixes (symbol bullets, RTL, links).
- Playwright tests with a fake host that serves fixture packages (generated by
  running the stream A fixture generator, or by python-docx directly when the
  core is not merged yet; tests read `.docx` files under `tests/fixtures/`).

### Stream C: hosts, packaging, CI, and release engineering

Owns `src/windows/`, `src/linux/`, `macos/`, `installer/`, `packaging/`,
`brand/`, `scripts/` (except the stage script), `tests/hosts/`,
`tests/owner/`, `tests/Test-LeanDoc.ps1`, `.github/`, the host and package
sections of `CMakeLists.txt`, `CHANGELOG.md`, `docs/releases/v0.1.0.md`, and
`scripts/Test-ReleaseEngineering.mjs`.

- Copy LeanMark 0.3.0 hosts and adapt them to SPEC section 5 and the protocol.
- Open-in-editor resolution on each platform; single instance and tabs on
  Windows and Linux; settings and recent files; package serving.
- Build, package, and smoke scripts; `build.yml` and `pages.yml` modelled on
  LeanMark; winget manifests; owner measurement scripts; brand mark and icons.
- Until stream A merges, build against a stub core in `tests/hosts/stub/`
  that returns a fixed report and package, kept out of release builds.

## Phase 3 thorough testing

A dedicated test agent, separate from the three build streams, runs
[TEST_PLAN.md](TEST_PLAN.md) on the integrated build. It is not a code review.
It covers:

- **Usage:** 15 scripted end-to-end tasks for the three audiences, through the
  real host on Linux, with Windows and macOS subsets in CI.
- **UI:** contact sheets of every fixture in both views and themes on all three
  platforms, a LibreOffice side-by-side, pixel baselines for chrome states,
  window sizes and scaling, keyboard, axe-core accessibility, and zoom.
- **Performance:** launch, first page, tab, view, find, zoom, and scrolling
  timings on 3, 300, and 1,000-page documents against fixed budgets.
- **Memory footprint:** full process tree baselines, per-document and per-tab
  cost, leak checks over repeated open, close, tab, and view cycles, and idle
  growth, against fixed budgets and LeanMark on the same runner.
- **Security in use, install lifecycle, and the corpus rendered end to end.**

The agent builds the harnesses in `tests/usage/`, `tests/perf/`, and
`tests/visual/`, adds a `perf-memory` CI job, files every defect, and fixes
them with the owning code. The phase ends when the exit criteria in the test
plan are met and every result is recorded in `docs/VALIDATION_STATUS.md`.

## Phase 2 review checklist

- Every SPEC requirement traced to code and a test, or listed as a gap.
- Security fixtures pass in the core, reader, and Linux host smoke.
- `grep` for banned words, em dashes, and AI attribution returns nothing.
- Licences: only MIT, BSD, Apache-2.0, zlib, OFL in shipped files;
  `THIRD_PARTY_NOTICES.md` complete.
- A real Linux render screenshot of each feature fixture inspected by eye.
